# 开发日记自动记录规则

本项目根目录维护一份 `开发日记.md`，作为课程设计的过程性材料与答辩依据。AI 必须自动维护它，无需用户提醒。

## 触发时机（满足任一即记录）

每次对话中，只要产生了以下任一结果，在回复结束前自动追加一条日记：

- 作出了决策（技术选型、方案取舍、分工、流程约定等）
- 对项目文件或配置作了改动（新增、修改、删除）
- 得出了明确结论（问题排查结果、调研结论、接口约定等）

纯问答、闲聊、无结论的讨论**不记录**。

## 记录格式

追加到 `开发日记.md` 末尾，严格使用以下模板：

```markdown
## YYYY-MM-DD 主题（一句话）

**参与人**：

**讨论主题**
-

**作出的决策**
-

**改动**
- 文件/模块：做了什么

**待办**
-
```

- 日期取当天实际日期
- 没有内容的字段写「无」，不要省略字段
- 语言简洁，一事一条，多条目按时间顺序追加，不改动历史条目

## 记录后自动提交

每次追加日记后，自动执行：

1. `git add 开发日记.md`
2. `git commit -m "docs: 开发日记 - <本次主题>"`
3. `git push`

若 push 前发现远程有新提交（队友更新过），先 `git pull --rebase`，如有冲突则保留双方条目、按日期排序合并后再 push。

## 其他改动同步提交

如果本次对话还改动了代码或其他文件，与日记分开提交：代码改动单独一个 commit（按 `<type>: <description>` 规范），日记记录单独一个 commit。
